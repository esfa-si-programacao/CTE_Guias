1. Sobre este manual

O Estúdio 4C do CTE Informático dispõe de uma infraestrutura dedicada à computação de alto desempenho, inteligência artificial local, virtualização e armazenamento resiliente, composta por três sistemas integrados:

  • Estação de Trabalho AI — TUXEDO Atlas XL (Gen1 Intel) (INV-006): computador de secretária Linux otimizado para treino e inferência de modelos de Inteligência Artificial, Machine Learning, Processamento de Linguagem Natural (LLMs locais), Visão Computacional e conversão/renderização de vídeo.
  • Servidor NAS — QNAP TVS-h874 (Core i7 · 32 GB RAM) (INV-223, instalado junto ao servidor): servidor de armazenamento de 8 baías SATA + 2× M.2 NVMe com sistema operativo QuTS hero (ZFS), Virtualization Station (máquinas virtuais acedidas pelos computadores e MacBooks do CTE) e Container Station.
  • Proteção Elétrica — UPS APC Smart-UPS SMT LCD RM SmartConnect (INV-224, junto ao servidor): unidade de alimentação ininterrupta que protege o NAS e o bastidor contra falhas de energia e picos de tensão.
Antes de iniciar a primeira sessão: Complete a Carta de Utilizador IA & Virtualização. Para administração de contas, pools ZFS, snapshots e manutenção preventiva, consulte o Manual Técnico e Manutenção.

2.3 UPS APC Smart-UPS SMT LCD RM SmartConnect (INV-224)

Instalada junto ao servidor no Estúdio 4C, a UPS APC Smart-UPS alimenta e protege o NAS QNAP TVS-h874 contra cortes súbitos de eletricidade. Um corte abrupto de corrente num servidor com escrita ativa ou máquinas virtuais a correr pode degradar volumes; a UPS mantém o servidor ligado a bateria e ordena o encerramento limpo caso a falha elétrica se prolongue.

5. Gestão de GPU/VRAM, ambientes Python (venv) e LLMs locais

Na estação TUXEDO Atlas XL, siga sempre o fluxo de trabalho abaixo para garantir que o seu projeto corre à velocidade máxima da placa gráfica sem interferir com outras turmas:

  1. Verificar o estado da GPU e VRAM:

    Abra um terminal e execute nvidia-smi. Verifique a linha de utilização de memória (ex.: MiB / MiB) e a lista de processos na parte inferior da tabela. Para acompanhar em tempo real durante um treino, use watch -n 2 nvidia-smi (prima Ctrl+C para sair).

  2. Criar e ativar um ambiente virtual isolado (.venv): 
    mkdir -p ~/projetos_turma/grupo1 && cd ~/projetos_turma/grupo1
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip

    Enquanto vir o prefixo (.venv) no terminal, qualquer comando pip install instala pacotes apenas na pasta do seu grupo.

  3. Executar modelos de linguagem locais (Ollama):
    • Antes de transferir um modelo novo, veja quais já estão instalados na estação com ollama list.
    • Para conversar ou testar um modelo local no terminal: ollama run llama3.2 (ou o modelo indicado pelo professor); escreva /bye para sair.
    • Para usar via API local em Python (porta 11434), aponte o seu script para http://localhost:11434/api/generate.
  4. Libertar a VRAM ao terminar:
    • Em JupyterLab / Jupyter Notebook: feche as células e clique em Kernel → Shut Down Kernel (ou no separador lateral Running Terminals and Kernels → Shut Down All).
    • Em scripts de terminal: aguarde que o processo termine ou interrompa com Ctrl+C e confirme com nvidia-smi que o seu PID desapareceu da lista da GPU.

6. Máquinas Virtuais, Containers e LEDs do NAS QNAP TVS-h874

Graças ao processador Intel Core i7-12700E (12 núcleos / 20 threads) e aos 32 GB de RAM, o servidor QNAP TVS-h874 permite executar sistemas operativos completos (Linux Ubuntu/Debian, Windows Server/11, appliances de cibersegurança ou redes) diretamente no navegador.

  • Usar uma Máquina Virtual na aula (Virtualization Station):
    1. Aceda ao painel web do QNAP e abra a aplicação Virtualization Station.
    2. Localize apenas a Máquina Virtual atribuída ao seu grupo (ex.: VM-TurmaA-Grupo1). Nunca desligue nem reinicie VMs de outros grupos!
    3. Clique em Iniciar (Start) e depois em Consola (Console) para abrir o ecrã da VM numa nova janela do navegador.
    4. No final da aula, caso se trate de uma VM de laboratório temporário, encerre-a de forma limpa a partir do menu do próprio sistema convidado (Shut Down) para libertar RAM e CPU do servidor.
  • Contentores leves (Container Station): Para serviços web, bases de dados (PostgreSQL/MariaDB) ou microserviços Docker, prefira contentores LXD/Docker na Container Station, que consomem muito menos memória RAM do que uma máquina virtual completa.

7. Proteção de dados ZFS, Snapshots e privacidade (RGPD)

  • Onde guardar cada tipo de ficheiro:
    • Durante o treino na Tuxedo Atlas XL, copie o dataset de leitura ativa para o SSD NVMe local (muito mais rápido por segundo para centenas de milhares de imagens pequenas), mas guarde sempre o código-fonte, resultados finais e checkpoints validados na pasta da turma no NAS QNAP.
    • Nunca deixe os únicos exemplares do seu trabalho em /tmp ou na pasta de transferências local da estação.
  • Recuperação de ficheiros com Snapshots ZFS: O sistema de ficheiros ZFS do QNAP cria fotografias instantâneas (Snapshots) regulares das pastas partilhadas. Se apagar ou corromper um ficheiro acidentalmente, avise logo o professor — é possível restaurar o ficheiro exato de horas ou dias antes sem afetar o resto da pasta.
  • Privacidade e RGPD em projetos de IA: Não carregue fotografias, gravações de voz ou dados pessoais identificáveis de colegas/terceiros sem consentimento expresso, e nunca escreva palavras-passe ou chaves de API privadas diretamente no código de notebooks partilhados (use variáveis de ambiente locais não partilhadas).

8.1 Script Python copiável — Diagnóstico de GPU/VRAM e Benchmark PyTorch

Guarde o código abaixo como teste_gpu_cte.py dentro do seu ambiente virtual (.venv) na Tuxedo Atlas XL e execute python3 teste_gpu_cte.py:

#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""Diagnóstico rápido de GPU/VRAM e benchmark CPU vs CUDA — CTE (Tuxedo Atlas XL INV-006)"""

import platform
import time

print("=== DIAGNÓSTICO DE AMBIENTE IA — CTE ESTÚDIO 4C ===")
print(f"Sistema: {platform.system()} {platform.release()} | Python: {platform.python_version()}")

try:
    import torch
except ImportError:
    print("PyTorch não está instalado neste ambiente virtual (.venv).")
    raise SystemExit(0)

print(f"Versão PyTorch: {torch.__version__} | CUDA disponível: {torch.cuda.is_available()}")

if torch.cuda.is_available():
    dev_name = torch.cuda.get_device_name(0)
    free_b, total_b = torch.cuda.mem_get_info(0)
    print(f"GPU detetada : {dev_name}")
    print(f"VRAM livre   : {free_b / (1024**3):.2f} GB livres de {total_b / (1024**3):.2f} GB totais")

    # Benchmark rápido de multiplicação de matrizes 4096x4096
    n = 4096
    a_cpu = torch.randn(n, n)
    b_cpu = torch.randn(n, n)
    t0 = time.perf_counter()
    _ = a_cpu @ b_cpu
    t_cpu = time.perf_counter() - t0

    a_gpu = a_cpu.to("cuda")
    b_gpu = b_cpu.to("cuda")
    torch.cuda.synchronize()
    t1 = time.perf_counter()
    _ = a_gpu @ b_gpu
    torch.cuda.synchronize()
    t_gpu = time.perf_counter() - t1

    print(f"Multiplicação {n}x{n} -> CPU: {t_cpu:.3f} s | GPU CUDA: {t_gpu:.4f} s (Aceleração: {t_cpu/max(t_gpu,1e-6):.1f}x)")
    del a_gpu, b_gpu
    torch.cuda.empty_cache()
    print("VRAM temporária do teste libertada com sucesso.")
else:
    print("Aviso: CUDA não detetado. Verifique drivers ou ambiente virtual.")
